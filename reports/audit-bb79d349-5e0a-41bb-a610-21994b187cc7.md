Both resend paths behave the same way — I verified this directly in the code rather than relying on the half-finished answer above.

**Short answer: yes, both "resend" buttons send email and text — but the text only goes out if two things are true: SMS (Twilio) is turned on for your account, and that signer has a phone number saved on file.** If either is missing, only the email goes, and the app tells you how many texts went out so you're not left guessing.

- **Report page — "Send Reminder" / "Remind All"** (`/api/send-agreement-reminder`): sends the email, then best-effort sends a text to any signer with a phone on file (if SMS is configured). The confirmation message says things like "Sent 2 reminder email(s) and 1 text(s)."
- **Agreements page — "Send / Resend"** (`/api/send-agreement-email`): same deal — email always, text best-effort under the same two conditions. Button shows "Sent ✓ (+1 text)" when a text went out.

Both routes were written to intentionally mirror each other's SMS behavior (there's a comment in the reminder route noting it's "in parity with" the other one). So this isn't a bug or inconsistency — nothing to fix here. No code changes made.
