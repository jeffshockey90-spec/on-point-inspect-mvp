# Popup cleanup — final check

I went through the app looking for any pop-up boxes that still look old, plus any spots where the new pop-up style isn't quite consistent. The good news: the big cleanup worked — almost every "are you sure?" box and message box in the app now uses the new matching style. I found two things still worth tidying up: four spots that still show the old plain browser box instead of the new styled one, and a handful of "delete this" boxes that don't turn red like the other delete warnings do.

## Findings

### A few spots still pop up the old plain box, not the new styled one
- **What's happening:** The cleanup replaced the old "are you sure / OK" style boxes everywhere, but it didn't cover a different kind of box — the ones where the app asks you to *type something in* (like naming something). Four of those still use the browser's old plain gray box instead of matching FLOW's look.
- **Why it matters to you:** It's a small thing, but it'll stand out — right after dozens of other popups now look clean and on-brand, these will suddenly look like a plain old browser alert, which feels unfinished.
- **How urgent:** Worth doing eventually — it's cosmetic, nothing is broken or unsafe, it just looks out of place.
- **Where it is:**
  - Typing a label onto a photo during photo markup, and editing that label afterward (`components/PhotoMarkupEditor.tsx` lines 383 and 547)
  - Naming a new service type when setting up an agreement (`app/agreements/AgreementLibraryManager.tsx` line 827)
  - Naming a limitation you're saving for reuse later (`components/SectionLimitations.tsx` line 836)
  - A diagnostics "copy this log" box used for troubleshooting, not something clients or inspectors normally see (`components/AILiveInspectionCamera.tsx` line 2520)
- **What I'd do:** Add a small typed-input version of the same styled popup (the earlier work already built the "are you sure" one — this would just be a sibling of it) and swap these four spots over to it.

### Some "delete this" warnings don't turn red like the others
- **What's happening:** Most of the delete/remove warnings in the app now show a red button to make clear it's a destructive action (delete a photo, delete an inspection, remove a team member, etc.). But a few delete confirmations were written slightly differently and ended up keeping the plain teal "OK" color instead — so they look like a routine message rather than a warning.
- **Why it matters to you:** It's not a safety hole (you still have to click confirm either way, nothing deletes by accident), but it's inconsistent — the same kind of action ("delete this permanently") looks low-stakes in some places and urgent-red in others, which is exactly the kind of mismatch you asked me to look for.
- **How urgent:** Fix soon — quick to fix and it's a visible inconsistency on real delete actions, not just a minor leftover.
- **Where it is:**
  - Deleting a finding from a report, in two different places that both handle it (`components/FindingActions.tsx` line 67 and `components/EditableFinding.tsx` line 621)
  - Deleting a post from your changelog (`app/dashboard/owner/changelog/OwnerChangelog.tsx` line 127)
  - Deleting a report template (`app/settings/report-templates/ReportTemplatesEditor.tsx` line 109)
- **What I'd do:** Mark these as "danger" style like the other delete warnings so the button turns red to match.

### One small polish note (not a problem, just an observation)
- **What's happening:** On the styled warning boxes, only the button itself changes color for a warning or danger message — the title text and the box border stay the same for every type of message.
- **Why it matters to you:** Nothing wrong today, but if you ever want a danger warning to catch the eye even faster (before someone reads the button), there's a bit more room to make it pop.
- **How urgent:** Worth doing eventually — purely a nice-to-have, not something anyone has complained about.
- **Where it is:** The shared pop-up box used everywhere in the app (`components/ConfirmProvider.tsx`).
- **What I'd do:** Leave as-is unless you want extra visual punch on the danger warnings later.
