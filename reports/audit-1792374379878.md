I checked the workflow behind this very chat — the "Claude Coder" screen where you type to me, attach pics/docs, ask me to look into things, and tap "Build this." Overall the core idea is sound and safe (nothing ever reaches your live app without you tapping Approve), but I found a few real gaps in how it handles the in-between moments — while something is still being looked into or built.

### If I say "I'm on it" but something's broken behind the scenes, you'd never know
- **What's happening:** When you ask me to look into something, I reply right away ("On it, I'll check that...") and then a separate process goes off to actually do the checking. If that hand-off fails for any reason — a connection hiccup, an expired access key, GitHub being slow — there's no error message. I just told you I'm on it, and then... nothing ever comes back. No "something went wrong" notice, ever.
- **Why it matters to you:** You'd be left thinking I'm quietly working on something, possibly for a long time, when in fact nothing is happening at all. You'd only realize if you got impatient and asked again.
- **How urgent:** Fix soon — it's the kind of silent failure that quietly erodes trust in this tool.
- **Where it is:** This Coder chat screen, right after you ask me to check something (`app/api/owner/coder/chat/route.ts`).
- **What I'd do:** If the hand-off fails, have me say so right away in the chat instead of staying quiet.

### Closing or refreshing this chat wipes the whole conversation
- **What's happening:** This chat doesn't save itself anywhere. If you refresh the page, switch tabs away and back, or your phone's browser kills the tab in the background, every message you and I exchanged is gone — including your original question.
- **Why it matters to you:** If a review or a build is still running when that happens, the answer will eventually show up in a chat that's now empty — with no memory of what you originally asked. You'd see a report or a "here's your change" card land with zero context.
- **How urgent:** Fix soon — this is the main thing that would make the tool feel unreliable day to day.
- **Where it is:** This Coder chat screen (`components/CoderConsole.tsx`).
- **What I'd do:** Save the conversation (not just "something's in progress") so it survives a refresh, the same way other settings in FLOW are saved centrally instead of only on one device.

### A finished review or change can get "lost" if you switch devices or clear your browser
- **What's happening:** The only record of "I'm waiting on task X" lives in your current browser's local memory, not in FLOW's database. If you ask me to check something on your phone, then later open FLOW on your laptop (or clear your phone's browser data) before I finish, the answer never makes it back to you on any device — it just sits unseen.
- **Why it matters to you:** You could ask something important, get distracted, switch devices like you normally would, and simply never see what I found. You wouldn't even know to go looking for it.
- **How urgent:** Fix soon — pairs with the point above; both come from the same root cause (nothing about an in-progress task is saved centrally).
- **Where it is:** Same Coder chat screen, the "waiting on" tracking (`components/CoderConsole.tsx`).
- **What I'd do:** Track in-progress tasks in the database tied to your account, not just in one browser's memory, so any device picks up the result.

### Pictures and documents you attach here aren't kept private
- **What's happening:** When you attach a screenshot or a document in this chat, it's stored in the same general storage area used for things like your logo — which isn't locked down to just you. It's the same category of issue you already had me fix for the W9 tax form a while back, just for a different type of file this time.
- **Why it matters to you:** If a screenshot ever shows a client's name, address, or payment details, it's sitting somewhere that isn't private to your account, indefinitely (it's also never cleaned up afterward). The address isn't easy to guess, so the practical risk is low, but it's not truly locked down either.
- **How urgent:** Worth doing eventually — low real-world risk today, but it's the same pattern that bit you before.
- **Where it is:** Attaching a file in this Coder chat (`app/api/owner/coder/upload/route.ts`).
- **What I'd do:** Store these attachments the same locked-down way the W9 documents were fixed, and clean them up after a while.

### Tapping "Build this" twice can start two competing changes
- **What's happening:** Nothing stops you from tapping "Build this" again while a change is already being built for the same conversation — there's no "already working on it" lock on that button.
- **Why it matters to you:** You could end up with two separate changes being built for the same request, which is confusing to review and wastes time, though it wouldn't break anything since you still approve each one by hand.
- **How urgent:** Worth doing eventually — a minor annoyance, not a risk.
- **Where it is:** The "⚡ Build this" button on this Coder chat screen.
- **What I'd do:** Grey out "Build this" while a change for the current conversation is already in progress.
