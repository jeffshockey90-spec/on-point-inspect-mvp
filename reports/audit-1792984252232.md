# Report Builder — Bug & Scrolling Check

I went through the report builder — the screen where you build out an inspection's sections, findings, and photos — looking specifically for bugs and scrolling glitches, on both phone and desktop. The scrolling itself holds up well: FLOW has already fixed several nasty "page jumps around while you're editing" bugs here, and those fixes are solid. I did find one real, repeatable glitch worth fixing, plus one older, higher-stakes item that's worth a 30-second double-check just to be sure, even though everything I can see says it's already fine.

## Findings

### Dragging (or arrow-reordering) a section can silently snap back to where it was
- **What's happening:** When you drag a section into a new spot — or use its up/down arrow buttons — FLOW shows the new order on your screen right away and saves it in the background a moment later. If you (or another inspector working the same report at the same time) make almost any other change — editing a finding's text, adding a note, checking a box — within about a second or two of that move, FLOW does a "catch up" refresh so that other change shows up. Right now, that catch-up refresh also re-reads the section order from the database — and if your section move hadn't finished saving yet, it reads the OLD order and your move visually undoes itself on screen, even though your original move usually does finish saving correctly a beat later.
- **Why it matters to you:** On a job where two inspectors are both working the same report, or any time you're quickly bouncing between reordering sections and editing a finding, you could watch a section you just moved jump back to its old spot for no visible reason. It looks broken and could make you redo the same move two or three times, thinking it "didn't take" — wasted time and a confusing moment, especially if it happens while you're on-site.
- **How urgent:** Fix soon — nothing is actually lost (closing and reopening the report shows the correct order), but it's a real, repeatable glitch on the single most-used screen in FLOW.
- **Where it is:** Report builder, dragging a section header or tapping its up/down arrows to reorder sections (`app/reports/[id]/ReportFindingsSortable.tsx`, the `moveSection` and `handleDrop` functions, roughly lines 966–1008).
- **What I'd do:** Give section reordering the same short "ignore other refreshes for a couple seconds while this save finishes" protection that reordering individual findings inside a section already has, a few lines above it in that same file — it's a proven fix already working elsewhere on this exact screen, just not applied to section-level moves yet.

### Worth a 30-second check: make sure a months-old database fix for photo reordering actually went through
- **What's happening:** A while back, dragging photos into a new order inside a finding was built before the spot to actually store that custom order existed in the database — so those drags silently did nothing. The fix had two parts: someone had to add that missing storage spot by hand directly in the database (a one-time, one-line change), and then the code that reads photos back out in your chosen order — used everywhere: client reports, PDFs, the client portal, and realtor downloads — was turned on. Both parts are in the code today, and the team has kept building more features on top of this for weeks since, without ever needing a "whoops, fix the missing photos" follow-up — which is a strong sign the one-time database change was done. I can't 100% confirm that from the code alone, though, and if it turned out NOT to have been done, every report's photos and videos would quietly vanish — the exact same kind of incident this project has been bitten by once before.
- **Why it matters to you:** This is about as high-stakes as it gets if it were wrong — missing photos in a client's report is a real liability and trust problem. But every signal I can find says it's already fine, so I don't want to alarm you over something that's very likely a non-issue.
- **How urgent:** Nothing to fix — just a quick confirm. Next time you're in any finished report, open a finding with two or more photos and drag them into a different order; if the new order sticks (and the photos are all still there in your client-facing report), you're good.
- **Where it is:** Any report → a finding with 2+ photos → drag to reorder (behind the scenes: `supabase/add-photos-sort-order.sql` for the one-time database change, and the photo-ordering code in `app/share/[id]/page.tsx`, `app/reports/[id]/print/page.tsx`, and `app/api/realtor-report-download/[id]/route.ts`).
- **What I'd do:** Just do the 30-second check above once. If it works, no action needed — and worth knowing for next time that the project's own internal notes have one slightly out-of-date line saying photos have no custom-order storage spot, which hasn't been true since this fix went in.

## What I checked and found healthy
- The scrolling fixes already in place for the report builder — keeping your spot on screen after editing, saving, or combining a finding; not collapsing every open section back closed on every refresh; not fighting your own scroll with an automatic jump — are all working as intended, on both phone and desktop.
- Reordering findings within a single section (the up/down arrows on each card) already has the right protection against the "snap back" problem described above — it's only section-level reordering that's missing it.
- The section drag-and-drop correctly falls back to simple up/down buttons on phones (native drag-and-drop doesn't work well on touch), so nothing is broken or missing on mobile there.
