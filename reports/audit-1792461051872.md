# Is the camera popup fix live? — Answer

**Short answer: No — not really.** Something was changed and shipped yesterday (Oct 19) that was meant to fix this, and it did fix part of the problem, but it used the wrong "layer number" and so the live camera still wins and still hides the popup. The "Discard and close camera?" box (and the Add/Edit Label boxes when opened from inside the live camera) will still be invisible in the field today.

## What I found

### The recent fix picked a layer number that's still lower than the camera's
- **What's happening:** Think of every screen and popup as being drawn on its own numbered sheet of plastic, stacked up — whichever sheet has the highest number is the one you actually see on top. Yesterday's change gave the popup box a very high number (2,147,483,000) and also changed *how* it's placed on screen so it always sits at the very top level of the app instead of getting buried inside a smaller box — both good, sensible improvements. But the live camera's full-screen sheet was already set to an even higher number (2,147,483,647 — the highest number the system allows at all), and that number was never touched. So the camera is still on a higher sheet than the popup, by 647. The popup is still behind the camera.
- **Why it matters to you:** This is the exact bug you flagged — the confirmation box that disappears when you try to close the live camera with something unsaved, and the Add/Edit Label boxes when they're opened from inside the live camera. It's still happening today, in the version that's live right now, for both the Field Tool camera and the Report Builder camera (since they're the same camera, as I confirmed for you earlier).
- **How urgent:** Fix now — same reasoning as before. An inspector tapping the X to close the camera mid-write-up still sees nothing happen, and their only way out is force-closing the app and possibly losing the write-up.
- **Where it is:** The popup's number is set in `components/ConfirmProvider.tsx` (line 129, currently 2,147,483,000). The live camera's number is set in `components/AILiveInspectionCamera.tsx` (line 2586, currently 2,147,483,647 — unchanged since before any of this started).
- **What I'd do:** Just lower the camera's number so it's below the popup's number (or raise the popup's number to match the camera's and make sure the popup is still placed after the camera on the page so it draws on top when the numbers tie). Either one-line change fixes it — the camera number is the simpler one to drop.

### Two other full-screen tools still use that same "highest number" setting, same as before
- **What's happening:** The Field Tool's plain (non-AI) photo camera (`components/FieldCamera.tsx`) and the full-screen photo zoom-in viewer used on reports (`components/ExpandableReportImage.tsx`) both still use that same highest-possible layer number. This hasn't changed since I last checked.
- **Why it matters to you:** Neither of these two currently ever opens one of the styled popup boxes, so they're not causing a visible problem today. But if anyone ever adds a confirmation box to either of those two tools in the future, it will hit this exact same invisible-popup bug again, for the same reason.
- **How urgent:** Worth doing eventually — not an active problem right now, just a landmine for later.
- **Where it is:** `components/FieldCamera.tsx` and `components/ExpandableReportImage.tsx`.
- **What I'd do:** Once the main camera's number is fixed, give these two the same treatment so the same mistake can't resurface here later.
