# Re-check: did the privacy fix actually close the gaps?

Good news first: two of the three things I flagged last time are genuinely fixed, and fixed well. But the main leak — a client document's text ending up somewhere permanent and public inside GitHub — is only half-closed. The part that's still open is a different door into the same room: the plain-English report itself can still carry a document's text into a GitHub page that never expires and that closing the request doesn't remove.

### The report Claude writes can still carry a client's document text into GitHub forever

- **What's happening:** The last fix stopped the document text from being written into the one-line description at the top of a GitHub request. But when you attach a PDF or text file and ask Claude to "look into" something, the actual write-up it produces — the report you read in the chat — can still quote or repeat pieces of that document's text if it's explaining its findings. That report gets saved as a file and shows up as the "changes" on the GitHub request, which is a page that stays on GitHub permanently — even if you just close the request without approving anything.
- **Why it matters to you:** This is the same core problem as before, just through a side door instead of the front door. A client's name, address, or payment details that were in an attached document could still end up sitting on a public-facing GitHub page forever, with no 14-day cleanup, no matter whether you approve or dismiss the result.
- **How urgent:** Fix soon — same reasoning as last time. It only happens when you attach a document and then ask Claude to look into something, not every conversation, but it undercuts the privacy promise just as much as the issue that was already fixed.
- **Where it is:** The Coder chat, when you attach a PDF/text file and ask Claude to check something (`lib/coder/taskPrompt.ts` — nothing stops the write-up from quoting a document's text; `.github/workflows/claude-task.yml` — the write-up becomes a file on the request page; `components/CoderConsole.tsx` — where the document's text is pulled in).
- **What I'd do:** Tell Claude explicitly, in the instructions it's given for writing these reports, to describe what a document says in its own words and never copy its text directly — a summary like "the attached file contains a client's name and address" instead of the actual name and address. That keeps the usefulness of the report without carrying the private details along with it.

### What got fixed — confirmed working

- **A document's text leaking into the one-line request description:** Fixed. That description is now just a plain intro sentence and a reference number — no document text, no chat text at all.
- **A document's text sticking around forever in your saved conversation:** Fixed. The saving-as-you-type step now throws away the extracted document text before anything touches the database — it only exists in the chat while you're actively looking at it, and disappears on refresh/New chat. The original 2-week cleanup on the file itself is unaffected and still works.
- **Chat silently stopping saving if a conversation gets too big:** Fixed. You'll now see a clear warning in the chat telling you to start a New chat, instead of it failing with no notice.
