# Referral service alerts — what I found

**On "which referral service did my client request today":** I can't pull that answer from here — this session only lets me read the app's code, not look at today's actual activity. But I can tell you exactly where to look yourself, right now:
- **Home security (Secure 24):** Go to your main dashboard and find the "Secure 24 Referral Leads" box. It lists the most recent clients who opted in, with their name and the date. Check if today's date shows up there.
- **Insurance referral:** There is currently no screen anywhere that lists these. The only way you'd know is if you got an email today with the subject starting "Home insurance referral:" — you're copied on that email automatically when a client opts in (as long as your email is set up correctly on your profile). Check your inbox, or the "Sent Emails" screen in the app and look for that subject line.

So: check those two spots for today's date. Below is what I found while looking into the push-alert request — including the fact that right now, nothing pings you the moment either of these happens.

## Findings

### 1. There is currently no instant alert when a client requests a referral service — for either program
- **What's happening:** When a client asks to be connected with either your home-security partner (Secure 24) or an insurance agent, nothing notifies you right away. The home-security request gets logged quietly in the background; the insurance request sends an email (and copies you on it), but neither one pops up as a phone alert the way a signed agreement or a new booking does today.
- **Why it matters to you:** This is exactly the gap you flagged — right now, the only way to know a client asked for a referral "today" is to go looking for it (checking a dashboard box or digging through email), not have it pushed to you. You could easily miss a hot lead for a day or more.
- **How urgent:** Fix soon — this is the feature you asked for, and the app already has working phone-alert plumbing used for other events (like "agreement signed"), so building this is a matter of hooking the referral moment into that same alert system, not inventing something new.
- **Where it is:** The home-security opt-in (`app/api/secure24/opt-in/route.ts`) and the insurance opt-in (`app/api/insurance-referral/opt-in/route.ts`) — neither currently triggers a phone alert. The working alert system they'd hook into lives at `lib/push.ts`.
- **What I'd do:** Add a phone alert that fires the moment a client opts into either referral, saying who the client is and which service they asked for, same as the existing "agreement signed" alert does today.

### 2. There's no on/off switch yet for this kind of alert — but the settings screen already has the right pattern to add one to
- **What's happening:** Your Settings page already has a full "Notifications" area with on/off switches for things like appointment reminders and report-ready alerts. There's no switch yet for "client requested a referral," since that alert doesn't exist yet (see #1 above).
- **Why it matters to you:** This is the toggle you asked for — it isn't built, but it's a small, well-understood add since the settings screen already has a working on/off switch design used for several other alert types.
- **How urgent:** Fix soon — goes hand-in-hand with #1; they should be built together.
- **Where it is:** The Notifications section of Settings (`components/NotificationSettings.tsx` and `app/api/settings/notifications/route.ts`).
- **What I'd do:** Add one more switch in that same list: "Referral requested," using the exact same on/off style already used there.

### 3. The insurance referral has no dashboard list at all — you're relying entirely on email
- **What's happening:** While checking where you could currently see "who requested what," I noticed the home-security program has a basic list screen (client name + date), but the insurance referral program has nothing like it — the only record you get is the email you're copied on.
- **Why it matters to you:** If that email ever doesn't reach you (goes to spam, or your profile email is out of date), you'd have zero way to know a client asked for an insurance referral — no screen to double-check against, unlike the home-security side.
- **How urgent:** Worth doing eventually — not urgent on its own, but worth bundling in if you're already having the builder add referral alerts, since a simple list screen would make the new phone alert easy to double-check against.
- **Where it is:** Insurance referral request handling (`app/api/insurance-referral/opt-in/route.ts`); the home-security program's list screen that could be used as a model is the "Secure 24 Referral Leads" box (`components/Secure24LeadsPanel.tsx`).
- **What I'd do:** Add a similar simple list for insurance referral requests (client name, date, which agent it went to) next to the existing home-security one.

### 4. The existing home-security list doesn't make "today" obvious at a glance
- **What's happening:** The "Secure 24 Referral Leads" box shows dates like "Oct 23, 2026" for each recent request, but doesn't call out which ones happened today specifically — you have to read each date yourself.
- **Why it matters to you:** Minor, but worth knowing: if you're using that box to answer "did anyone request this today," you'll need to read the dates carefully rather than it being flagged for you.
- **How urgent:** Worth doing eventually — small polish, not a real problem.
- **Where it is:** Same "Secure 24 Referral Leads" box (`components/Secure24LeadsPanel.tsx`).
- **What I'd do:** Nothing urgent — if the phone alert in #1 gets built, this becomes much less important since you'd be told the moment it happens instead of hunting for it.
