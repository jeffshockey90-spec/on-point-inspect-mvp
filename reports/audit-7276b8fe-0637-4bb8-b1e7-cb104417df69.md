## Does resending an agreement send email and text?

**Yes — both the in-report button and the separate Agreements-page button try to send an email AND a text**, not just one or the other. I was wrong in my earlier draft saying the report's button only emails — I re-checked the live code and that's not what it does.

- **"Send Reminder" / "Remind All" on the report itself** → calls `/api/send-agreement-reminder`, which sends the email and then also attempts a text to that same signer.
- **"Send / Resend" on the separate Agreements page** → calls `/api/send-agreement-email`, which does the same: email first, then also attempts a text.

Both paths only skip the text if one of two things is true:
1. **Texting isn't turned on for the app at all** (the Twilio connection isn't configured) — this is an app-wide switch, not per-inspector, so it's either on for everyone or off for everyone.
2. **That specific signer doesn't have a phone number saved** on their contact card — no phone means no text, even if texting is otherwise on.

If a text does go out, the confirmation message tells you ("Sent ✓ (+1 text)" or similar); if it's skipped, you won't see an error — it just quietly skips the text and still sends the email.

This was a read-only check — no code changed. Let me know if you want visibility added here too (e.g. showing on the report whether texting is even turned on, or flagging when a signer has no phone on file so the text got silently skipped).
