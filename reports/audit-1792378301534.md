# Checking the new Coder privacy update (private attachments, saved conversation, cleanup)

I went through the change you just had built — private storage for pictures/docs
you attach in the Coder chat, the chat now remembering your conversation, and a
daily cleanup job. The storage and database parts of that are built correctly.
But there's one real gap: a document's text can still leak out of the private,
time-limited system into a place that isn't private or time-limited at all,
whenever you ask Claude to look into something or build a change. Details below,
worst first.

### A client's document text can end up inside GitHub, outside the protection you just built

- **What's happening:** When you attach a PDF or text file and then either ask
  Claude to "look into" something or tap **Build this**, the text pulled out of
  that document rides along in the request sent to GitHub (where the real work
  happens). GitHub then writes that text, word for word, into the description of
  the Pull Request it opens for you, and it also sits in that job's run log.
- **Why it matters to you:** The whole point of today's change was to keep a
  client's name, address, or payment info — the kind of thing that can be in a
  screenshot or PDF — private and short-lived. That now holds true for the file
  itself (14 days, locked to your account). But the text Claude read out of that
  file doesn't follow the same rule once you ask it to look into something or
  build a change — it gets copied into a GitHub pull request and a log, both of
  which stick around indefinitely and aren't cleaned up by the new 14-day job.
  So a client's private details could live on in GitHub long after the original
  attachment is gone.
- **How urgent:** Fix soon — it only fires when you attach a document (not a
  picture) and then ask Claude to act on it, so it's not every conversation, but
  it directly undoes the privacy protection you just paid to build.
- **Where it is:** The Coder chat, when you attach a PDF/text file and then send
  a message or tap "Build this" (`app/api/owner/coder/chat/route.ts`,
  `components/CoderConsole.tsx`, `lib/coder/taskPrompt.ts`, and
  `.github/workflows/claude-task.yml` where the text lands in the PR description).
- **What I'd do:** Either strip the document's extracted text out of what gets
  sent to GitHub (keep it only inside the private chat), or make clear to
  yourself that anything you attach and then act on should be treated as no
  longer private once you do.

### A document's text sticks around in your saved chat forever, even after the file itself is deleted

- **What's happening:** The new cleanup job deletes the actual picture/document
  file after 14 days, exactly as intended. But the text Claude already pulled out
  of a PDF or text file is saved as plain words inside your ongoing conversation,
  and that conversation has no automatic expiry — it stays until you personally
  start a "New chat."
- **Why it matters to you:** If a document had a client's details in it, those
  details are still sitting in your saved conversation well after the 14-day
  cleanup removed the original file. The "it goes away after 2 weeks" promise
  only really applies to the file, not to what was read out of it.
- **How urgent:** Worth doing eventually — it's a gap in the privacy story, not
  something actively breaking today.
- **Where it is:** The Coder chat's saved conversation
  (`app/api/owner/coder/conversation/route.ts`, `components/CoderConsole.tsx`).
- **What I'd do:** Either also expire document text out of old saved messages
  after the same 14 days, or just get in the habit of starting a "New chat"
  after you're done discussing anything with a client's private info in it.

### If a conversation gets too long, it can quietly stop saving — with no warning to you

- **What's happening:** Your conversation is capped at 2MB (roughly a very long
  chat with several documents attached) before saving it is refused. Right now,
  if that happens, nothing tells you — the chat just silently stops saving from
  that point on.
- **Why it matters to you:** If you ever hit that ceiling (a long-running
  back-and-forth with a few PDFs attached could get there), a refresh or
  switching devices could lose everything after that point, and you'd have no
  idea it happened until you noticed the chat looked different.
- **How urgent:** Worth doing eventually — it takes an unusually long
  conversation to hit this, but silent data loss is worth closing off.
- **Where it is:** The Coder chat's "save as you type" behavior
  (`components/CoderConsole.tsx`, the save effect that calls
  `app/api/owner/coder/conversation/route.ts`).
- **What I'd do:** Show a small warning in the chat if a save fails, the same
  way it already warns you when a "look into it" request fails to start.

### One thing to double-check before you rely on this

- **What's happening:** This update needs two one-time database setup steps run
  in Supabase (creating the private storage area, and the table that saves your
  conversation) before any of it works.
- **Why it matters to you:** If those two steps haven't been run yet, attaching
  a file or your conversation being remembered will quietly fail.
- **How urgent:** Fix now, if you haven't already — otherwise nothing to do.
- **Where it is:** Two setup files the builder flagged when this went in
  (`supabase/coder-attachments-private-bucket.sql` and
  `supabase/coder-conversations.sql`).
- **What I'd do:** If you're not sure you ran them, try attaching a photo in the
  Coder chat and refreshing the page — if the photo and the conversation are
  still there after refresh, both steps are in place.
