# Did we already build agreement status visibility?

**Short answer: Yes, most of it is already live right now — the last change we merged a few minutes ago added it. You can already see "Sent on [date]," "Signed on [date]," "Unsigned/Pending," and a full "Waived" explanation (who waived it, when, and why) on the agreement section of a report. The one piece that is NOT built yet is showing when an agreement got replaced by a newer one** (this happens when a client already signed, you then add an add-on service to the job, and they have to re-sign to cover the new scope — right now that swap happens silently with no on-screen note). Details below.

## Findings

### 1. Sent / Signed / Pending / Waived are already visible today — this is done
- **What's happening:** On the agreement section of a report, each client or realtor who needs to sign shows their own line with a colored status tag (Signed, Unsigned, or Waived) plus a plain date line underneath: "Sent: [date]" if you've sent it but they haven't signed, "Signed: [date]" once they have. If you waive the requirement entirely, there's a separate purple box showing the reason you typed in, who waived it, and the date it was waived.
- **Why it matters to you:** This is exactly the "what happened and when" visibility you asked for — it's already working, nothing more to build here.
- **How urgent:** N/A — already done, confirmed by reading the actual code.
- **Where it is:** The "Signature Tracking" box inside a report (`components/AgreementStatusPanel.tsx`), with the "Sent" date piece added in the change we just merged.
- **What I'd do:** Nothing — this part is finished. Worth a quick look next time you're in a report just to confirm it looks right to you.

### 2. When a client has to re-sign because you added an add-on, the old signature quietly disappears with no note that it was replaced
- **What's happening:** If a client already signed, and you later add an extra service (like a sewer scope or mold test) to that same job, they're asked to sign again to cover the new scope. Behind the scenes the system keeps the old signed copy on file but marks it "replaced" and hides it from view — only the newest signature shows. There's no note anywhere on screen saying "this replaced an earlier signature" — it just looks like they signed once, with no history of the earlier one.
- **Why it matters to you:** For your own records this is almost always fine, since the newest signature is the one that actually matters legally (it covers the full job). But if you or a client ever asked "didn't they already sign this before the add-on was added?", there's currently nothing on screen to show that — you'd have to ask the builder to go look at the stored records directly.
- **How urgent:** Worth doing eventually — this only comes up on jobs where you add a service after the original agreement was signed, which probably isn't most jobs.
- **Where it is:** The same "Signature Tracking" box inside a report, and the behind-the-scenes agreement saving logic (`components/AgreementStatusPanel.tsx`, `app/api/sign-agreement/route.ts`, `app/api/signed-agreements/route.ts`).
- **What I'd do:** Add a small note under the current signature, like "Replaced an earlier signature from [date] after an add-on was added," so the history isn't hidden.

### 3. "Who signed it" is already visible, just not called out separately
- **What's happening:** You asked about showing who signed — right now each signature line already sits right under that person's name and role (client, co-client, realtor), so you can already tell who signed just by looking at which row shows "Signed." There's no separate "signed by [name]" label, but it's not needed since the name is already right there.
- **Why it matters to you:** Nothing missing here in practice — just flagging it so you know it's covered and we don't rebuild something that already works.
- **How urgent:** N/A — already covered.
- **Where it is:** Same "Signature Tracking" box inside a report (`components/AgreementStatusPanel.tsx`).
- **What I'd do:** Nothing needed.
